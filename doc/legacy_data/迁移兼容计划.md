# 旧数据迁移兼容计划（测试阶段）

## 1. 目标与范围
- 目标：在不执行正式迁移的前提下，完成旧 Excel 数据结构梳理、字段兼容设计、清洗规则定义。
- 范围：`doc/legacy_data` 下 4 份历史文件：
  - `立项-工地及项目信息录入_20260224182334.xlsx`
  - `操作员日志_20260224192305.xlsx`
  - `管理员日志_20260224192420.xlsx`
  - `贯通报告_20260224192443.xlsx`

## 2. 旧表结构观察摘要

### 2.1 立项-工地及项目信息录入
- 主体字段：工程全称、工程简称、负责人、地址、省市区、地勘土质、机型、管材、管材规格、备注。
- 子行字段（同一项目多行）：标段、桩号、标段长度、设计坡度、管径。
- 数据特征：
  - 项目信息在首行，后续行常出现“仅补充标段信息”的空主体行。
  - 长度/管径混有单位字符串（如 `104m`、`D1500`）。

### 2.2 操作员日志
- 主体字段：工程名称、桩号、日期时间、班次、操作员、本班/累计顶进与下管、压力电流、土质、偏差、现场照片、备注。
- 数据特征：
  - 偏差字段存在“方向 + 数值”跨行补充。
  - 现场照片可能是逗号分隔多 key。
  - 班次为中文（白班/夜班）。

### 2.3 管理员日志
- 主体字段：工程名称、日期、今日详情、明日计划、提交人、提交时间。
- 数据特征：
  - “提交人”列重复；日志正文为多行文本。
  - 当前系统可直接承载“今日详情”，但“明日计划”需补字段。

### 2.4 贯通报告
- 主体字段：工程名称、标段、贯通日期、开工日期、顶进天数、管径、总长度、总下管数量、偏差、其他事项、提交人。
- 数据特征：
  - 偏差常以“方向 + 数值”分行补充。
  - 管径为字符串样式（如 `D2200`）。

## 3. 与现有数据结构的兼容评估

### 3.1 已可承载
- 项目主信息、标段、操作员日志、管理员日志、贯通报告均已有核心表。
- 施工日志/项目日志/贯通报告与当前业务流程一致。

### 3.2 主要缺口
- 缺少旧系统主键保留位（`legacy_data_id`）用于追溯去重。
- 缺少部分历史业务语义字段：
  - 项目：省市区/详细地址、地勘土质、机型、管材规格。
  - 标段：设计坡度、管径。
  - 操作员日志：压力电流、土质、偏差方向与数值、原始照片 key 串。
  - 管理员日志：明日计划。
  - 贯通报告：开工日期、顶进天数、总下管数量、偏差拆分字段。

## 5. 清洗与导入规则（正式迁移前）

### 5.1 标准化规则
- 班次：`白班 -> day`，`夜班 -> night`。
- 管径：`D1500` 解析为 `1500`；无法解析时保留原字符串到兼容字段。
- 长度：去单位 `m` 后转数值；无法转数值的写入原始扩展字段。
- 偏差：拆分为 `deviation_direction` 与 `deviation_value_mm`。
- 照片：逗号分隔 key 转数组；无效 key 记录到清洗日志。

### 5.2 关联策略
- 项目匹配优先：`工程简称 -> project_code`，其次 `工程全称 -> project_name`。
- 标段匹配优先：`桩号/标段文本 -> project_section.section_code`。
- 未匹配记录进入“人工确认池”，不直接入主表。

### 5.3 去重策略
- 若存在 `legacy_data_id`，按 `legacy_data_id` 幂等。
- 无 `legacy_data_id` 时采用指纹：
  - 操作员日志：`project + section + log_date + shift + operator`
  - 管理员日志：`project + log_date + submitter + title`
  - 贯通报告：`project + section + report_date`

## 6. 迁移执行建议（测试阶段）
- 阶段A：读取 Excel -> 标准化 -> 生成清洗结果文件（不入库）。
- 阶段B：抽样比对（10%）确认字段映射。
- 阶段C：全量导入到测试库，做业务验收。
- 阶段D：冻结映射规则，准备生产迁移窗口。

## 7. 可裁剪字段建议
- 可去掉（仅保留原始扩展）：
  - 重复“提交人”列
  - 空白辅助列
  - 无业务含义的旧系统展示列
- 保留原则：只要可能影响追溯/审计，优先保留到兼容字段或扩展 JSON。

## 8. API 暴露审查结论（当前阶段）
- 现状：`packages/api/src/routes/project.ts` 与 `packages/api/src/routes/log.ts` 的现有创建/更新接口仍以业务主字段为主，未强制写入新增兼容字段。
- 结论：在“测试阶段仅做兼容、不做正式迁移”前提下，兼容字段保持为存储预留位是安全的，不会影响当前在线流程。
- 约束：正式导入前需通过单独导入脚本写入兼容字段，不建议在现有业务表单 API 中直接暴露全部旧字段，避免污染日常录入体验。
