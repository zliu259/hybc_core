# 库房与资产任务队列重构 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把库房与资产模块从表格/单据入口重构为 Web 管理端任务队列驱动系统，并为下一阶段小程序执行端预留稳定后端模型。

**Architecture:** 后端保留现有 `asset`、`warehouse`、`warehouse-work-order` 路由和基础表，采用增量迁移增加任务包、手册、任务证据和组合方案字段。Web 端重构为库房负责人视角的总控台、任务调度台、返库检查维护、顶管机组合方案、操作手册库和设备追溯；小程序端暂不实现 UI，但后端接口和配置下发结构提前设计。

**Tech Stack:** Cloudflare Workers + Hono + TypeScript + D1 + Queue；Web 使用 Vue 3 + Element Plus + TypeScript；小程序为企业微信原生页面；AI 走现有 AI Slot 与 task_queue。

## 3. 状态与术语约定

### 3.1 资产状态建议

有状态资产状态建议统一为：

- `idle`: 在库可用。
- `using`: 项目使用中。
- `returned_quarantine`: 返库隔离，待检查。
- `inspection`: 检查中。
- `maintenance`: 维护中。
- `servicing`: 保养中。
- `modification`: 改装中。
- `reserved`: 已预留。
- `in_transit`: 运输中。
- `scrapped`: 已报废。

现有 `quarantine` 可迁移或兼容映射为 `returned_quarantine`。如果短期不迁移数据库枚举，API 层和前端展示层必须把两者视为同一业务含义。

### 3.2 任务状态建议

库房任务状态建议统一为：

- `draft`: 草稿。
- `pending_assignment`: 待派工。
- `assigned`: 已派工。
- `in_progress`: 执行中。
- `submitted`: 已提交待审核。
- `completed`: 已完成。
- `rejected`: 审核退回。
- `cancelled`: 已取消。

### 3.3 任务包状态建议

- `open`: 已创建。
- `in_progress`: 执行中。
- `completed`: 已完成。
- `exception`: 有异常。

## 6. P2 返库检查维护闭环

**目标:** 返库签收后自动创建检查任务，任务未完成前阻塞再次出库。

**Files:**

- Modify: `packages/api/src/routes/warehouse.ts`
- Modify: `packages/api/src/services/warehouse-task.ts`
- Modify: `packages/api/src/routes/asset.ts`
- Test: `packages/api/src/routes/warehouse-return-gate.test.ts`

**Backend behavior:**

- 入库单执行时，如果明细包含 `tracked_asset_id`，且来源是项目返库，自动创建返库检查任务。
- 返库设备状态进入 `returned_quarantine` 或兼容 `quarantine`。
- 出库 gate 必须检查是否存在未完成的阻塞任务。
- 检查任务完成后，如果结果为通过，资产可回到 `idle`。
- 检查任务完成后，如果结果为需维护，自动生成维护任务，资产进入 `maintenance`。
- 维护任务完成后，资产回到 `idle`。

## 11. P7 小程序执行端接口规划

**目标:** 先把小程序执行端所需后端接口稳定下来，页面实现放到下一阶段。

**API planning:**

- `GET /api/v1/warehouse/work-order/mobile/my-tasks`
  - 返回当前操作员任务包和任务列表。
- `GET /api/v1/warehouse/work-order/mobile/task/:id`
  - 返回任务详情、步骤、手册、必拍照片要求。
- `POST /api/v1/warehouse/work-order/mobile/task/:id/start`
  - 开始任务。
- `POST /api/v1/warehouse/work-order/mobile/task/:id/submit`
  - 提交简报和结果。
- `GET /api/v1/warehouse/work-order/mobile/config`
  - 返回任务类型、步骤组件、字典、手册显示配置。
- `GET /api/v1/warehouse/work-order/mobile/package`
  - 返回当前操作员任务包。

**Mobile design constraints:**

- 小程序页面应通过后端配置渲染任务步骤。
- 新增任务类型不应强依赖小程序发版。
- 小程序不提供最终派工。
- 小程序不提供复杂组合方案制定。

**Steps:**

- [x] 先写接口规划文档。
- [x] 后端实现只返回稳定通用结构，不暴露 Web 管理字段。
- [x] API 需要通过 WeCom `userid` 过滤“我的任务”。
- [x] 提交任务时必须校验任务已分配给当前用户。
- [x] 上传证据时必须校验证据属于当前任务。
