### 2.4 返库检查维护闭环

- 项目返库入库执行时，有状态设备进入 `returned_quarantine`。
- 同时自动创建 `source = return_receipt` 的返库检查任务。
- 返库检查通过时设备回到 `idle`，出库 gate 可重新放行。
- 返库检查未通过时自动创建维护跟进任务，原检查任务保留记录但取消阻塞，由维护任务继续阻塞设备。
- 维护任务完成复核后，设备回到 `idle`，出库 gate 可重新放行。
- 出库 gate 已接入任务阻塞判断，未完成阻塞任务会阻止再次出库。

## 4. 未开始

### 4.1 P8 AI 辅助接入

已完成：

- 任务调度建议触发入口：Web 调度台可按当前筛选或勾选任务创建 `warehouse_task_dispatch_recommendation` 异步任务。
- 调度建议 payload 明确 `no_auto_dispatch = true`，AI 结果只进入任务队列结果，不直接改变执行人、任务包或计划日期。
- 顶管机组合推荐触发入口：Web 组合方案台按所选机芯创建 `tbm_composition_recommendation` 异步任务。
- 组合推荐 payload 明确 `no_auto_apply = true`，AI 只推荐壳体/操作台候选、改装风险和原因，不自动创建组合方案。
- 手册 AI 草稿完成后会回填对应 `warehouse_manual_version.content_json`，并把 `ai_draft_status` 更新为 `completed`；失败时更新为 `failed`。
- AI 任务类型补充 `warehouse_task_dispatch_recommendation`、`tbm_composition_recommendation` 和 `warehouse_manual_draft`。

仍需补齐：

## 5. 下一阶段建议

下一阶段建议定义为“Stage 2A：Web 管理闭环补强”。目标不是做小程序页面，而是先把 Web 管理端和后端闭环补完整，避免小程序执行端接入后发现任务包、手册、组合方案规则不稳定。

### 5.1 优先任务包

1. 返库闭环测试与维护自动任务。
2. 任务包 UI 和批量派工。
3. 手册绑定规则与自动匹配。
4. 顶管机组合候选规则和组合转任务包。
5. 设备详情证据预览和筛选。

### 5.2 暂缓任务

- 小程序页面实现。
- AI 自动调度。
- AI 手册草稿。
- 大范围 UI 视觉重做。

暂缓原因：这些功能依赖任务包、手册绑定、组合方案规则稳定后再进入，避免小程序反复审核和 AI 结果无处落地。
