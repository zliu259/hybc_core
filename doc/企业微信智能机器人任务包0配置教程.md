# 企业微信智能机器人任务包 0 配置教程

> 目标：在进入真实联调前，冻结企业微信智能机器人工具调用协议、群机器人 Webhook 推送边界和项目群绑定参数。

## 1. 准备信息

需要提前准备：

- 企业微信管理员账号，具备配置智能机器人和群机器人的权限。
- 恒越 API 外网地址，例如 `https://api.hybcdg.com/api/v1/wecom`。
- 恒越 Web 管理端地址，例如 `https://web.hybcdg.com`。
- 一个内部测试群。
- 一个目标外部群，若第一阶段需要对外部群推送日志。
- 一个随机生成的工具调用 token，建议长度不少于 32 位。
- 如需同步外部客户群，准备具备客户联系权限的 Secret，部署为 `WECHAT_CUSTOMER_CONTACT_SECRET`。

不要把真实 Webhook URL、token 或企业微信密钥写入代码、D1 或文档。

## 2. 在管理端完成基础配置

进入 Web 管理端：

```text
系统底层与引擎 -> 企业微信智能机器人
```

在系统级页面完成：

- 复制“工具清单地址”，填入企业微信智能机器人后台。
- 复制“工具调用地址”，填入企业微信智能机器人后台。
- 填写“工具 Token”并保存；保存后不回显，只显示是否已配置。
- 给群机器人 Webhook 分配一个 `Webhook Secret Ref`，例如 `prod-east`。
- 粘贴企业微信群机器人 Webhook URL 并保存；保存后不回显。
- 维护“群聊目录”：外部客户群可点击“同步外部客户群”；内部普通群若企业微信接口不能枚举，则手动登记群名、群 ID 和可选 Webhook Ref。

后端会把工具 token 写入 KV `wecom:tool-token`，把 Webhook URL 写入 KV `wecom:group-webhook:<secret_ref>`。D1 只保存 `secret_ref`，不保存真实 URL。

保留的环境变量：

```text
WECOM_TOOL_WEB_BASE_URL=https://web.hybcdg.com
WECOM_GROUP_WEBHOOK_PROXY_MODE=direct
WECHAT_CUSTOMER_CONTACT_SECRET=<客户联系 Secret，可选>
```

`WECOM_BOT_TOOL_TOKEN` 仍可作为部署级兜底 Secret；如果管理端已保存 token，KV 中的 token 优先生效。

## 3. 创建群机器人 Webhook

参考企业微信开发文档：`https://developer.work.weixin.qq.com/document/path/91770`。

在内部测试群执行：

1. 打开目标企业微信群。
2. 添加或管理群机器人。
3. 新建机器人，例如命名为“恒越日志通知”。
4. 复制机器人 Webhook URL。
5. 给该 URL 分配一个恒越内部引用名，例如 `prod-east`。

把复制到的 Webhook URL 粘贴到管理端“群机器人 URL”，并保存到对应 `Webhook Secret Ref`。

命令行写 KV 只作为兜底方式，不作为常规配置路径。

## 4. 验证 Webhook 推送

保存 Webhook 后，在项目工作区创建或编辑项目群绑定，选择群聊目录中的群，或手动输入群聊 ID，填写相同的 `Webhook Secret Ref`，保存后点击“测试推送”。

期望结论：

- 内部群可以收到“测试推送”markdown 消息。
- 若外部群也可以创建群机器人并收到消息，则外部群可走 Webhook 直推。
- 若外部群不能创建或不能接收 Webhook，则第一阶段不要启用外部群自动推送，后续走客户群群发 fallback。

验证完成后，把结论写入 `doc/开发记录.md`：

```text
## YYYY-MM-DD HH:mm (TZ)

### 目标
验证企业微信智能机器人和群机器人 Webhook 能力。

### 结论
- 智能机器人工具接入形态：HTTP API / MCP / 待确认。
- 工具调用认证方式：固定 token / 签名 / 其他。
- 工具调用上下文：是否携带 group_chat_id、bot_id、caller_userid。
- 内部群 Webhook：可用 / 不可用。
- 外部群 Webhook：可用 / 不可用，fallback 为客户群群发。
```

## 5. 配置智能机器人工具调用

参考企业微信智能机器人文档：`https://open.work.weixin.qq.com/help2/pc/21663`。

第一阶段按 HTTP API 工具接入配置；如果后台明确支持 MCP，再开启 MCP 任务包。

页面会直接展示实际地址。企业微信后台建议配置：

```text
工具清单地址：GET https://api.hybcdg.com/api/v1/wecom/tools/manifest
工具调用地址：POST https://api.hybcdg.com/api/v1/wecom/tools/call
认证 Header：x-wecom-tool-token: <管理端保存的工具 Token>
Content-Type：application/json
```

调用请求体应能表达以下结构：

```json
{
  "tool": "get_project_overview",
  "input": {
    "project_id": 7
  },
  "context": {
    "group_chat_id": "<企业微信群 ID>",
    "bot_id": "<智能机器人 ID>",
    "caller_userid": "<提问人 userid>"
  }
}
```

必须在后台实测并记录：

- 企业微信是否允许配置固定 Header。
- 企业微信是否自动传入群 ID、机器人 ID、提问人 userid。
- 企业微信是否要求工具清单使用它自己的 schema 格式。
- 企业微信是否支持 MCP；若支持，记录 MCP 服务 URL、鉴权和工具 schema 约束。

## 6. 在恒越后台绑定项目群

进入 Web 管理端：

```text
项目管理 -> 项目工作区 -> 项目群绑定
```

新增绑定：

- 绑定名称：例如“东线项目群”。
- 群聊 ID：从下拉选择系统群聊目录中的群；若暂未入库，可直接输入企业微信工具调用上下文里的 `group_chat_id`。
- 机器人 ID：如企业微信上下文提供 `bot_id`，同步填写。
- 允许工具：第一阶段只选只读工具。
- Webhook Secret Ref：填写前面保存的引用名，例如 `prod-east`。
- 启用能力：内部群可同时启用“问答工具”和“日志推送”。

保存后点击“测试推送”。

验收结果：

- 页面按钮有 loading，不允许重复点击。
- 企业微信群收到“测试推送”。
- 页面“推送结果”出现 `TEST_SEND` 且状态为 `sent`。
- 若失败，页面“推送结果”记录 `failed` 和错误原因。

## 7. 只读工具验收清单

第一阶段只允许这些工具：

- `get_project_overview`
- `list_project_sections`
- `get_section_progress`
- `get_latest_manager_logs`
- `get_latest_operator_logs`
- `get_project_risk_summary`
- `get_equipment_summary`
- `get_public_log_link`

验收方式：

1. 在企业微信群中 @ 智能机器人，询问项目概况。
2. 确认机器人调用 `get_project_overview`。
3. 确认返回内容只包含项目基础信息，不包含财务敏感字段。
4. 在 Web 管理端查看“工具调用记录”，状态应为 `success`。
5. 询问未授权工具或写入动作，应该被拒绝。

## 8. 任务包 0 完成标准

任务包 0 完成时必须有以下结论：

- 智能机器人第一阶段接入形态：HTTP API 或 MCP。
- 工具调用鉴权方式已确定。
- 上下文字段 `group_chat_id`、`bot_id`、`caller_userid` 是否可用已确定。
- 内部群 Webhook 已验证。
- 外部群 Webhook 是否可用已验证；若不可用，已确认 fallback。
- 至少一个项目完成后台绑定，并完成测试推送。
- `doc/开发记录.md` 已追加验证记录。

未完成任务包 0 前，不开放写入工具。
