# 库房与资产任务队列重构方案

## 1. 背景与结论

当前库房与资产代码已经具备 `asset_type`、`tracked_asset`、`inventory`、`stock_order`、`tracked_asset_configuration`、`warehouse_asset_work_order` 等基础能力，但前端仍以台账、单据、表格为主要入口。后续正式投入业务前，应把库房运营重构为“任务队列驱动”的模式。

本次重构的核心结论：

- 资产模型继续保留两类：有状态资产和数量型物资。
- 顶管机相关资产按组合资产处理，机芯是组合与生命周期的核心对象。
- 操作台根据所选机芯和项目要求推荐搭配。
- 所有库房工作统一归库房负责人负责，不设置设备负责人。
- 最终派工权属于库房负责人和超级管理员。
- Web 端负责管理、方案、派工、监督、手册维护和 AI 辅助。
- 小程序端负责操作员执行，下一阶段实现；本阶段只规划接口和执行模型。
- 返库签收后必须自动创建检查或维护任务，未完成前不得重新进入可出库状态。
- 任务完成证据必须绑定到设备、任务、单据和手册版本，形成可追溯时间线。

## 2. 目标用户与权限口径

### 2.1 超级管理员

超级管理员是全局兜底角色，拥有以下能力：

- 查看和干预全部仓库、任务、资产和手册。
- 配置角色、规则、状态字典、AI 辅助开关。
- 对异常任务、紧急出库和特殊放行进行最终处理。
- 查看所有追溯记录和审计记录。

### 2.2 库房负责人

库房负责人是库房运营的唯一业务责任口，拥有以下能力：

- 最终派工和调整任务包。
- 处理返库签收、检查、维护、改装、组合、出库复核和盘点差异。
- 发布或审核操作手册。
- 审核任务完成结果，包括照片、简报和异常说明。
- 使用 AI 建议进行任务调度和组合方案制定。
- 对未完成检查维护的设备进行放行控制。

### 2.3 库房操作员

库房操作员主要使用企业微信小程序，不以 Web 为主要工作入口：

- 查看“我的任务”。
- 扫码确认设备。
- 按任务步骤执行。
- 查看绑定的操作手册。
- 拍照、语音或短句填写结果。
- 提交任务完成材料。

操作员不负责方案制定、最终派工、规则配置、手册发布和复杂调度判断。

### 2.4 办公室与经理

办公室与经理不直接派工，主要能力是：

- 发起项目设备需求或出入库需求。
- 查看任务进度、设备可用性和异常。
- 参与审批。
- 查看追溯、报表和风险提示。

## 3. 业务对象模型

### 3.1 有状态资产

有状态资产继续使用 `tracked_asset` 作为基础实体。典型对象包括：

- 机芯
- 机壳
- 操作台
- 可追溯的重要设备
- 需要维保、改装、调拨、报废和生命周期追踪的资产

有状态资产必须具备：

- 唯一资产码。
- 当前状态。
- 当前仓库或项目。
- 事件时间线。
- 文档与照片证据。
- 任务历史。
- 组合历史。

### 3.2 数量型物资

数量型物资继续使用 `asset_type + inventory` 管理。典型对象包括：

- 消耗品
- 易损件
- 常规备件
- 不需要独立身份码的物料

数量型物资的核心能力：

- 按仓库记录数量。
- 支持出入库、调拨、消耗登记。
- 支持安全库存预警。
- 支持盘点差异处理。

### 3.3 顶管机组合模型

顶管机组合应以机芯为中心：

- 机芯：核心生命周期对象，决定主要能力、接口、规格和操作台匹配范围。
- 机壳：可与机芯组合，可能因项目留地下报废。
- 操作台：根据机芯能力、控制接口和项目要求搭配。

组合方案不是单纯记录三个资产 ID，而是一个业务过程：

1. 选择项目需求。
2. 选择机芯。
3. 系统推荐可搭配机壳。
4. 系统推荐可搭配操作台。
5. 标记是否需要改装。
6. 生成检查、维护、改装、组合和出库任务。
7. 任务完成后形成当前有效组合。

## 4. 核心运营流程

### 4.1 返库流程

返库流程必须强制任务闭环：

1. 出入库单或小程序扫码完成返库签收。
2. 系统把设备状态置为 `returned_quarantine` 或沿用当前实现中的 `quarantine`。
3. 系统自动创建返库检查任务。
4. 若检查发现问题，自动或手动衍生维护、保养、改装或报废任务。
5. 检查与必要维护完成前，设备不得进入 `available_now` 或可出库池。
6. 完成任务时，照片、简报、操作人、时间、手册版本写入设备事件时间线。

### 4.2 出库流程

出库流程由库房负责人在 Web 端制定，操作员在小程序执行：

1. 办公室、经理或库房负责人发起项目设备需求。
2. Web 端形成组合方案或物资清单。
3. 库房负责人确认任务包。
4. 系统生成出库前检查、维护、改装、装车复核任务。
5. 操作员逐项执行。
6. 所有阻塞任务完成后，出库单可执行。
7. 执行结果写入资产事件、库存流水和任务归档。

### 4.3 任务派发流程

任务派发必须支持手动与 AI 辅助：

1. 系统根据业务动作自动生成任务池。
2. AI 给出任务优先级、推荐负责人、预计耗时和风险提示。
3. 库房负责人确认派工。
4. 操作员在小程序收到任务包。
5. 任务超时、照片不足、结果异常时回到 Web 端提醒库房负责人。

AI 不拥有最终派工权。

### 4.4 操作手册流程

操作手册是库房知识沉淀体系：

1. 手册按任务类型、资产类型、型号、组件角色绑定。
2. 任务执行页自动展示匹配手册。
3. 操作员可以在任务中补充经验说明。
4. AI 根据历史简报、照片说明和异常处理记录生成手册草稿。
5. 库房负责人或超级管理员审核发布。
6. 已发布手册形成版本，任务完成记录必须保存当时使用的手册版本。

## 5. Web 端四个重构板块

### 5.1 库房总控台与任务调度台

这是 Web 端第一入口，替代当前以资产台账或出入库单为入口的方式。

核心模块：

- 今日任务总览：待分配、待执行、执行中、待审核、超时、异常。
- 返库风险：已签收未检查、检查未通过、需维护。
- 出库准备：待检查、待维护、待改装、待装车、可执行。
- 人员任务包：每个操作员今日任务量、超时量、完成量。
- AI 建议：优先级、推荐分配、风险解释。
- 快捷动作：创建任务、批量派工、调整优先级、审核结果。

页面应面向库房负责人，不面向普通操作员。

### 5.2 返库检查与维护闭环

该板块负责把返库设备从“已回库”变为“可再次出库”。

核心模块：

- 返库签收列表。
- 自动生成的检查任务。
- 检查项模板。
- 维护任务衍生。
- 强阻塞提示。
- 照片与简报审核。
- 设备状态流转记录。

关键原则：

- 返回库房即进入隔离或检查状态。
- 检查任务未完成，不允许出库。
- 维护任务未完成，不允许出库。
- 管理特殊放行必须记录原因、风险确认和审批人。

### 5.3 顶管机组合方案工作台

该板块负责处理高频改装和组合。

核心模块：

- 机芯列表。
- 机芯详情能力参数。
- 可搭配机壳推荐。
- 可搭配操作台推荐。
- 当前组合、历史组合、计划组合。
- 需改装项标记。
- 组合方案生成任务包。
- 组合方案转出库准备。

设计原则：

- 以机芯为中心，而不是以整机编号为中心。
- 操作台根据机芯推荐，不作为独立随意选择项。
- 组合方案必须能生成后续任务。
- 组合完成后写入设备事件时间线。

### 5.4 操作手册与经验库

该板块服务库房长期运营。

核心模块：

- 手册目录。
- 手册版本。
- 绑定规则：任务类型、资产类型、型号、组件角色。
- 图文步骤。
- 必拍照片要求。
- 常见异常与处理方法。
- AI 草稿生成。
- 人工审核发布。

手册不是普通文件附件，而是任务执行的标准依据。

## 6. 小程序规划

小程序在下一阶段实现，但本阶段必须提前规划后端接口和任务模型，避免 Web 端设计与移动端执行脱节。

### 6.1 小程序首页

首页只展示：

- 我的任务数。
- 紧急任务。
- 今日任务。
- 待补材料任务。
- 已完成任务。

### 6.2 小程序任务执行页

单个任务固定步骤：

1. 扫码确认设备。
2. 查看操作手册。
3. 按检查项执行。
4. 拍照或上传附件。
5. 语音或短句填写结果。
6. 提交。

### 6.3 小程序更新策略

由于小程序更新需要审核，无法实时发布，本次规划必须做到：

- 任务类型和步骤尽量由后端配置下发。
- 小程序只实现稳定通用组件。
- 新增手册、检查项、照片要求、任务说明不依赖小程序发版。
- 小程序后端接口最后实现，但数据结构应在 Web 端重构时预留。

## 7. AI 辅助边界

AI 辅助分为三类：

### 7.1 任务调度辅助

AI 输入：

- 任务类型。
- 资产状态。
- 项目计划。
- 人员任务量。
- 历史耗时。
- 超时风险。

AI 输出：

- 推荐优先级。
- 推荐操作员。
- 推荐原因。
- 风险提示。

最终确认人是库房负责人或超级管理员。

### 7.2 组合方案辅助

AI 输入：

- 项目需求。
- 机芯参数。
- 机壳参数。
- 操作台兼容规则。
- 历史组合效果。
- 当前库存与状态。

AI 输出：

- 推荐组合。
- 需改装说明。
- 不可用原因。
- 备选方案。

AI 不直接改变资产状态。

### 7.3 手册与简报辅助

AI 输入：

- 任务结果。
- 操作员短句或语音转文字。
- 照片说明。
- 历史维修记录。

AI 输出：

- 任务简报草稿。
- 手册草稿。
- 异常摘要。
- 经验沉淀建议。

手册发布必须人工审核。

## 8. 后端模型调整方向

现有表可以继续复用，但需要增量补充以下能力：

### 8.1 任务模型增强

在 `warehouse_asset_work_order` 基础上增强：

- 任务来源：返库自动生成、出库准备、人工创建、AI 建议。
- 任务优先级。
- 任务包 ID。
- 分配人。
- 审核人。
- 执行端类型：Web、小程序。
- 任务步骤 JSON。
- 必拍照片要求。
- 手册版本引用。
- 完成证据汇总。

### 8.2 任务包模型

新增任务包概念：

- 任务包编号。
- 负责人，即操作员。
- 创建人，即库房负责人或超级管理员。
- 状态：待执行、执行中、已完成、异常。
- 包内任务列表。
- 计划日期。
- 优先级。

### 8.3 手册模型

新增手册体系：

- 手册主表。
- 手册版本表。
- 手册绑定规则表。
- 手册附件或图片表。
- AI 草稿与审核状态。

### 8.4 组合方案模型

在 `tracked_asset_configuration` 基础上补充：

- 组合方案状态。
- 方案来源。
- 推荐结果。
- 需改装项。
- 操作台与机芯匹配规则。
- 生效与失效原因。

### 8.5 证据模型

任务完成证据需要同时绑定：

- 任务 ID。
- 资产 ID。
- 组合配置 ID。
- 出入库单 ID。
- 操作手册版本 ID。
- 文件 Key。
- 证据类型。
- 拍摄或上传人。
- 时间。

## 9. 前端信息架构

### 9.1 新 Web 菜单建议

`库房与资产`

- 库房总控台
- 任务调度台
- 返库检查维护
- 顶管机组合方案
- 出入库计划
- 消耗品与库存
- 公司盘库
- 操作手册库
- 设备追溯

### 9.2 操作员 Web 权限

操作员不作为 Web 主用户。若保留 Web 权限，仅允许查看有限信息，不提供复杂配置和派工能力。

### 9.3 现有页面迁移

- `views/warehouse/work-order.vue` 重构为任务调度台的一部分。
- `views/warehouse/dispatch.vue` 重构为总控台和组合方案的可用性视图。
- `views/warehouse/stock-order.vue` 从制单页重构为出入库计划页。
- `views/asset/detail.vue` 强化为设备追溯页。
- `views/asset/ledger.vue` 降级为查询视图，不作为主入口。
- `views/warehouse/templates.vue` 可合并到操作手册库或组合模板。

## 10. 验收标准

Web 端第一阶段验收：

- 库房负责人可以从一个总控台看到所有待处理任务。
- 返库签收后能自动生成检查任务。
- 检查或维护未完成的设备不能进入可出库状态。
- 任务可以分配给操作员并形成任务包。
- 任务完成后照片与简报能进入设备时间线。
- 顶管机组合方案可以以机芯为中心生成任务。
- 操作手册可以维护、绑定和版本化。
- AI 辅助只给建议，不绕过人工确认。

小程序规划验收：

- 已定义小程序任务执行所需接口。
- 已定义后端配置下发结构。
- 已明确哪些能力不依赖小程序发版。
