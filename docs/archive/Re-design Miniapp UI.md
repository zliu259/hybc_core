# 企业微信小程序 UI 与 AI 交互设计蓝图 (按 Tab 架构分配版)

## 1. 设计核心理念：为现场而生 (Field-First)

考虑到现场操作人员的受教育程度及工作环境，设计必须遵循**“极低认知负荷”**原则：

1. **图形胜于文字 (Graphic-Driven)**：所有状态、分类、警告，必须配有直观的插画、大图标或 Emoji，避免纯文本堆砌。

2. **红绿灯视觉系统 (Traffic Light System)**：全局严格使用“红（禁止/危险/故障）、黄（警告/需确认）、绿（安全/正常/通过）”三种本能颜色。

3. **零键盘输入 (Zero-Typing)**：全面引入语音转文字（STT）与 AI 语义提取，用“说”代替“写”。

4. **语音播报反馈 (Voice Feedback)**：对于 AI 解析的结果或重要操作提示，系统提供 TTS (Text-to-Speech) 语音朗读，让看不清字的人也能“听懂”系统反馈。

5. **大触控区与防呆 (Poka-yoke)**：严格采用 TDesign 的特大尺寸组件，关键操作需长按或滑动解锁，防止误触。

## 2. 全局导航架构 (App Architecture)

弃用传统的树状菜单，采用极简的 **4 Tabs + 1 全局 FAB (悬浮按键)** 结构。

* **[悬浮居中键] 全局 AI 助手 (Global Helper FAB)**

  * **位置**：屏幕底部正中央悬浮一个带有**呼吸灯动画**的巨大蓝色按钮（内置麦克风图标 🎤）。不受 Tab 切换影响。

  * **强引导交互**：按住说话：“我要给某某建材付款10万” / “A顶段今天顶了3.5米”。系统通过 AI 意图识别，自动帮用户跳转到对应 Tab 的页面并填好表单草稿。

## 3. 页面分配与精细设计 (按 Tab 拆解)

### 3.1 【Tab 1】工作台 (Home) - 综合看板与应用门户

**定位**：小程序的默认首页，提供宏观的数据状态和所有功能的快捷大图标入口。

* **底部 Icon**：`icon="home"`

* **UI 页面拆解**：

  * **顶部欢迎与指标卡**：显示“早安，张工”。下方用极大字号显示当天的核心待办数字（如：🔴 3个待审批，🟡 2个库存预警）。

  * **九宫格大图标入口 (`t-grid`)**：

    * 提供所有高频操作的快捷入口。图标必须拟物化、尺寸巨大。

    * 🚜 [设备查验]、👷 [安全勘查]、📝 [双规日志]、💰 [发起报销] 等。

    * **🏗️ [创建项目] (动态显隐)**：仅 `LEADER` 和 `FIELD_MGR` 角色可见。点击进入“项目创建向导”，利用语音或地图选点（自动带入经纬度和省市区），通过“一问一答”的卡片形式快速完成新项目的初步立项。

    * 点击后直接跳转至对应的业务 Tab 或二级页面。

### 3.2 【Tab 2】现场 (Field) - 施工进度与实物管治中心

**定位**：与物理世界和工程进度强绑定的聚合页，是现场项目经理与施工员的核心阵地。

* **底部 Icon**：`icon="location"`

* **进入逻辑**：切入该 Tab 时，自动静默获取 GPS，顶部锁定显示当前所在的 `[XXX 项目]`。

* **包含的核心页面与交互**：

  * **功能 A：顶段进度大屏与工作段管理 (Progress & Sections)**

    * **交互流**：

      * **全局进度仪**：页面上方展示该项目总体的进度环形图 (`t-progress` type="circle")。

      * **顶段卡片流**：下方列出本项目所有的“顶段/工作段”。每个顶段卡片上有一条醒目的粗体进度条（例如：`[东线顶管] 120m / 300m`）。进度数据由底层的施工日志自动累加计算得出。

      * **顶段管理**：仅现场负责人可见右上角的 `[➕ 新增顶段]` 按钮。点击弹出向导，输入“顶段名称”与“设计总长度(米)”，即可在现场随时开辟新的施工段。已有顶段支持点击 `[编辑]` 修正总长度。

  * **功能 B：双轨日志填报 (Dual-Track Logging)**

    * **场景**：严格区分宏观的管理情况与微观的工程数据。页面提供两个巨大的分流按钮：

    * **流向 1 👉 `[📸 写现场概况 (管理日志)]`**

      * 侧重记录人、机、料、法、环。

      * 交互：占据半个屏幕的 `[按住说话 🎤]` 按钮 ➔ AI 提取并渲染**图形化卡片**（☀️ 太阳代表白班，🌧️ 阵雨代表天气，自动总结文字摘要） ➔ 必须强制调起相机拍摄不少于 1 张现场实景图 ➔ TTS 朗读卡片内容 ➔ 点击 `[✔ 提交]`。

    * **流向 2 👉 `[🚜 报顶进数据 (施工日志)]`**

      * 侧重精密工程数据，**强绑定特定顶段**。

      * 交互：首先弹出 `t-picker` 选择当前施工的 `[顶段名称]` ➔ 同样按住说话：“今天顶了3.5米，最大推力120吨，注浆量5方” ➔ **AI 自动提取关键数值**并填入带单位的数字输入框 (`t-input-number`) 中 ➔ 若填报后超出了该顶段的设计总长度，屏幕**闪烁红色警告**并弹窗提示 ➔ 确认无误后提交，系统将立即更新看板上的顶段进度条。

  * **功能 C：现场项目资料库 (Project Files)**

    * **场景**：现场收到的图纸变更单、签收单，随时拍照归档，与 Web 端互通。

    * **交互流**：点击 `[📁 项目文件]` 进入宫格视图 ➔ 点击大号加号 `t-upload` ➔ 选择拍照或微信聊天文件 ➔ 弹出底部抽屉选择“文件分类”（下拉选择：施工图纸、签收单据、整改报告）➔ 直接上传归档。

  * **功能 D：现场安全勘查 (Site Survey)**

    * **交互流**：点击巨大相机图标拍照 ➔ 强制打上经纬度/时间防篡改水印 ➔ **AI 增强现实 (AR) 式标注**（前端在照片原图上，直接用红色的矩形框圈出隐患，如未戴安全帽，并连线显示大字警告：`⚠️ 没戴安全帽`） ➔ 一键推送给相关人员。

  * **功能 E：物资与设备查验 (Asset & Equipment)**

    * **交互流**：全局扫一扫触发 ➔ 从底部弹出 `t-popup` 抽屉。抽屉顶部显示设备照片及**极大的状态图标（🟢 亮绿勾 / 🟡 橙感叹号 / 🔴 红叉号）**。提供拟物化快捷键（🔧 大扳手=报修，📦 纸箱=调拨）。点击报修调起相机，后台 AI 自动分析损坏部位，免手动打字描述。

### 3.3 【Tab 3】审批与申请 (Workflow) - 极速决断与发单中心

**定位**：领导审批决策，以及全员发起复杂业务流转（如付款、合同）的核心枢纽。

* **底部 Icon**：`icon="check-double"` (带红点 Badge 提示待办数)

* **UI 顶部分段器 (`t-segment`)**：分为 `[待我审批]` 和 `[发起申请]` 两个大模块。

* **包含的核心页面与交互**：

  * **功能 A：统一审批列表与快批 (Tasklist)**

    * **交互流**：分类展示待办任务。支持**左滑/右滑快捷操作 (`t-swipe-cell`)**。熟练的领导甚至不需要进详情，直接列表右滑即可完成快批。

  * **功能 B：审批详情与摘要 (AI Summary)**

    * **交互流**：点开单据，完全隐藏传统的密密麻麻几十个字段。

    * 顶部只显示一个 **AI 红绿灯摘要卡片**：

      * 🔴 **红灯拦截**：“超出合同总额！/ 供应商有黑名单记录！”

      * 🟡 **黄灯提醒**：“注意：该设备近期报修频繁，请核实采购必要性。”

      * 🟢 **绿灯放行**：“各项金额无误，合规。”

    * **动作确认**：废弃简单的点击按钮，改为类似接听电话的 **“滑动滑块解锁 (Slider)”**，向右滑动滑块 ➔ 释放 ➔ 播放“审批通过”印章飞入的动画，有效防误触。

  * **功能 C：极速对外发单与合同 (Smart Payment Wizard)**

    * **场景**：现场急需调拨资金或签发采购需求，手头没有电脑。

    * **交互流**：

      1. 点击 `[💸 发起对外付款]` ➔ 弹出大字号的数字键盘（而非普通输入框）。

      2. 录入预计金额（或语音报数）➔ **系统实时测算阈值**。

      3. **低于阈值**：直接显示“简易收款人选取器”，滑动提交付款申请。

      4. **高于阈值（需合同）**：系统自动语音提示：“*该金额需签署合同*”。屏幕平滑过渡至“合同简易向导”：

         * Step 1：扫码识别或语音录入乙方实体。

         * Step 2：拍照上传合同纸质件（AI 自动提取关键条款）。

         * Step 3：屏幕出现巨大 Switch 开关 **`[🔗 同时发起首笔付款]`**。若开启，提交合同时联动带出第一笔预付款申请，一次滑动，双流并行。

### 3.4 【Tab 4】我的 (Me) - 个人自助服务与数据追踪

**定位**：员工个人相关的资产、报销、单据追踪与信息维护。

* **底部 Icon**：`icon="user"`

* **包含的核心页面与交互**：

  * **功能 A：我的全业务申请追踪 (My Applications)**

    * **场景**：员工需要知道自己前天在现场提交的付款、昨天扫的报销发票现在卡在谁手里了。

    * **交互流**：

      * 进入 `[我的申请]` 看板，这是一个**统一的时间线追踪台**。

      * 用不同的 Icon 和颜色区分业务线：📝 合同、💸 付款、🧾 报销、📦 调拨单。

      * 状态极端扁平化：`[⏳ 排队中]` ➔ `[👨‍💼 王总审批中]` ➔ `[🟢 已打款/已通过]`。

      * 领导长期未批，支持提供一个 `[🔔 一键催办]` 按钮，通过企业微信下发催办卡片。

  * **功能 B：报销信封与票据填报 (Reimbursement)**

    * **交互流**：相机扫描发票 ➔ 屏幕显示半透明扫描框引导 ➔ 识别完成播放“叮”清脆音效并爆开绿色 ✅ 动画。

    * **智能查重防雷**：如果 AI 发现发票重复，手机发起**强烈震动 (`wx.vibrateLong`)**，屏幕弹出占据 1/3 大小的红色 ⛔ 警示牌：“这张票已经报过了！”

  * **功能 C：个人资质与证书 (Certificates)**

    * **交互流**：网格视图展示个人的上岗证、特种作业证。证书如果即将过期，整个卡片背景变为显眼的橙色/红色进行高亮预警。

## 4. 前端开发与交互强制约束 (Development Rules)

1. **图文绑定原则**：所有名词（如“挖机”、“白班”、“安全帽”、“报销”）在 UI 上出现时，前面必须紧跟一个对应的 Emoji 或 SVG 图标。

2. **触控热区放大**：按钮的最小高度不得低于 `48px`（TDesign 的 large 尺寸），按钮之间的间距不小于 `16px`。

3. **重要反馈多通道 (Multi-sensory Feedback)**：

   * 成功：绿色画面 + 勾型动画 + 轻微震动 (`vibrateShort`)。

   * 失败/警告：红色画面 + 叹号动画 + 强烈震动 (`vibrateLong`) + 警告音效/语音播报。

4. **禁止长列表滚屏与复杂表单**：一屏尽量只显示一个核心问题或卡片。复杂的业务（如创建顶段、发单立项）**必须**拆分为“一步一问”的卡片式向导（Wizard），配以粗体大字，杜绝长表单引起的认知崩溃。

## 5. 首期落地建议 (MVP 阶段路径)

1. **Sprint 1 (核心底座与 4 Tabs 搭建)**：

   * 搭建 4 Tabs 导航与悬浮全局麦克风 FAB，跑通 TDesign 的大尺寸组件。

   * 封装全局的“震动反馈”和“TTS 语音播报”基础工具类 `utils/interaction.js`。

   * 实现审批模块的“滑动解锁同意 (Swipe to Approve)”自定义组件。

2. **Sprint 2 (【现场】双规日志与顶段监控)**：

   * **重中之重**：构建“顶段大屏监控进度条”与“双规日志（现场概况 vs 顶进数据）”的视图结构。

   * 跑通顶段数据的 CRUD 操作（新增、编辑长度），确保小程序端与 Web 端的业务逻辑与权限控制一致。

   * 实现【项目文件】的拍照上传及分类打标链路。

3. **Sprint 3 (语音副驾与 AI 填报增强)**：

   * 对接微信同声传译插件，实现“现场概况”与“顶进数据”两种日志的 AI 语音结构化提取。

   * 开发勘查模块实景红框绘制（AR 效果）及设备扫码“红绿灯状态”弹窗。

4. **Sprint 4 (全员发单向导与报销闭环)**：

   * 攻克【审批】Tab 下的“极速对外发单”分步向导（带金额校验与合同自动衍生）。

   * 完成【我的】Tab 下的全量申请跟踪时间线及 OCR 票据识别/防重警告动画。
