# Web 端全角色页面重构与权限蓝图 (Vue 3 + PureAdmin)

## 0. 重构执行指引 (给前端团队)

1. **清理旧路由**：删除 `src/router/modules/` 下所有旧的按数据表划分的路由（如单独的 `entity.ts`, `dict.ts` 等）。
2. **重组路由树**：按照本文档的“模块划分”新建路由文件，通过 `meta.roles` 严格控制菜单可见性。
3. **组件复用**：页面结构变了，但底层的 API 请求函数 (`src/api/*.ts`) 保持不变。全面推行**卡片化（Card）**和**右侧抽屉（Drawer）**交互，减少全屏跳转。

## 1. 全局 UI 交互与组件规范 (Global UI/UX Guidelines)

为确保全平台操作体验的一致性，前端团队在重构与开发时必须严格遵守以下交互准则（基于 Element Plus 组件库）：

### 1.1 关系型数据选择（严格禁止文本手填）
* **项目选择 (Project Selection)**：所有涉及“选择所属项目”的场景，**强制使用支持模糊搜索的下拉选择器** (`el-select` 开启 `filterable`)。禁止让用户手动输入项目名称。
* **人员选择 (User Selection)**：分配人员、选择审批人、选择责任人时，**强制使用下拉选择器**。若人员较多，需支持按部门分组展示或支持拼音首字母检索。
* **业务关联选择 (Business Reference)**：选择“关联合同”、“关联工作段”时，需使用下拉框或点击弹出“选择器弹窗 (Dialog/Drawer)”，选中后将数据带回，严禁要求用户手动拷贝输入 ID 或流水号。

### 1.2 数据录入与防呆机制 (Input Validation)
* **金额与数字**：所有涉及金额（付款、报销、合同总价）、数量（物资调度数量）的录入，强制使用数字输入框（`el-input-number`）或定制的格式化组件，必须自带千分位并屏蔽非法字符输入。
* **时间与日期**：强制使用 `el-date-picker` 或 `el-time-picker`，禁止普通文本框输入日期。
* **字典项**：班次（白班/夜班）、状态类别等，必须通过拉取后端字典数据渲染为单选框（`el-radio`）或下拉框（`el-select`）。

### 1.3 页面布局与容器控制 (Layout & Containers)
* **抛弃全屏大表单跳页**：新建、编辑、详情查看等操作，**优先使用右侧抽屉（`el-drawer`）**覆盖在当前列表上方。保持用户的底层列表上下文不丢失。只有在逻辑极复杂（如新建复杂合同）时才考虑新开页签。
* **极简动作确认**：对于简单的状态流转（如“删除确认”、“提交审批”），优先使用 `el-popconfirm` (气泡确认框) 或 `el-dialog`，避免大动干戈。
* **主从拆分视图 (Split View)**：用于频繁核对的场景（如统一审批台、收发货核对），采用左侧导航列表（占宽 30%）+ 右侧详情与操作面板（占宽 70%）的布局。

### 1.4 状态与颜色语义 (Status & Color Semantics)
全局状态标签（`el-tag`）必须遵循统一的颜色语义：
* 🟢 **绿色 (Success)**：已完成、已打款、已签收、审批通过、状态良好。
* 🔵 **蓝色 (Primary)**：进行中、执行中、运输中、正常使用中。
* 🟠 **橙色 (Warning)**：待处理、待审批、预警、库存不足、即将过期。
* 🔴 **红色 (Danger)**：已驳回、已退回、报废、库存严重短缺、异常/故障。
* ⚪ **灰色 (Info)**：草稿、已取消、闲置、失效。

## 2. 角色定义与全局权限矩阵 (RBAC Matrix)

系统内置以下 5 个核心基础角色（通过 JWT Token 中的 `role` 字段区分）：

| 角色编码 | 角色名称 | 核心诉求 | 菜单/页面权限范围 | 
| :--- | :--- | :--- | :--- | 
| `EMPLOYEE` | 员工 | 快速报销、提交日志、少看无关信息。 | 个人中心、审批中心(限个人)、基础日志、发起对外付款(限个人)、项目面板(只读)、全局技术支持(仅提交与查看个人)。 | 
| `FIELD_MGR` | 现场管理人员 | 管工地、管设备、管材料出入库。 | 项目面板(项目内可编辑)、库房控制台(含制单与签收)、动态与日志。 | 
| `FINANCE` | 财务人员 | 严格把控资金进出、开票、打款执行。 | 财务监控台、收付款执行、报销批次处理。 | 
| `LEADER` | 经理/领导 | 看宏观数据、防范风险、快速审批决断。 | 全局大屏、项目总览、财务报表、审批流转。 | 
| `SUPER_ADMIN` | 超级管理员 | 维护系统规则、兜底排障、AI配置。 | **全部页面可见**，系统底层设置、全量业务数据运维、全平台技术工单处理。 |

## 3. 页面架构与精细设计 (按模块划分)

### 全局通用组件 (Global Components)

* **全局技术支持抽屉 (IT Support Drawer)**
  * **入口位置**：系统全局顶部导航栏 (Header) 右侧，放置一个醒目的“耳机/客服”图标按钮。
  * **可见角色**：`全部角色`
  * **UI 交互**：点击图标从右侧滑出 `el-drawer`，内部包含两个标签页 (Tabs)：
    * **Tab 1: 提交问题 (Submit)**：包含问题分类（下拉单选 `el-select`：账号问题、权限缺失、系统报错、功能建议等）、问题描述文本域、以及截图/附件上传区。点击 `[提交]` 后自动切换到列表页。
    * **Tab 2: 我的记录 (My Tickets)**：时间线或简易列表结构。展示自己提交的历史工单，状态标签区分（`待处理`: 橙色, `已解决`: 绿色）。点击单条可展开查看管理员的处理回复意见。
  * **API 对接**：`POST /api/v1/support/tickets` | `GET /api/v1/support/tickets?creator_id=me`

### 模块一：个人工作台 (Personal Workspace)
**可见角色：** `全部角色` (这是所有人的登录默认首页)

* **1.1 我的主页 (Dashboard)**
  * **UI 交互**：欢迎卡片（展示未读通知、待办数量）。提供快捷入口组（如：`[发起报销]`, `[填报日志]`, `[待我审批]`）。

* **1.2 我的报销与收款卡**
  * **UI 交互**：左侧为个人绑定的银行卡（卡片式），右侧为个人报销信封时间线（待核对 -> 审核中 -> 已打款）。
  * **API 对接**：`GET /api/v1/user/me/bank-accounts`；`GET /api/v1/reimbursement?creator_id=me`

* **1.3 个人资质与证书 (Personal Certificates)**
  * **UI 交互**：使用卡片网格 (Grid) 展示个人已上传的各类资质证书。提供拖拽上传区域，支持上传 PDF 和图片电子件。卡片上需展示证书名称、颁发日期及有效期（日期选择使用 `el-date-picker`），并对即将过期的证书进行显眼的颜色（橙色/红色）高亮预警。

### 模块二：审批流转枢纽 (Approval Center)
**可见角色：** `全部角色` (数据范围按人隔离)

* **2.1 统一审批台 (Unified Tasklist)**
  * **UI 交互**：**左列表 + 右详情（主从拆分视图）**。左侧按 `biz_type` 分类展示待办卡片；右侧渲染业务详情（支持预览合同 PDF 或风险报告），底部固定吸底操作条（包含绿色的通过、红色的驳回/退回按钮）。

### 模块三：项目与现场指挥 (Field Command)
**可见角色：** `全部角色` (数据范围与操作权限按项目参与度隔离)

* **3.1 项目选择大厅 (Project Hub)**
  * **UI 交互**：纯卡片网格，展示项目名、负责人、状态标记和环形进度条。取代枯燥的列表。右上角提供显眼的 `[+ 创建项目]` 按钮（仅 `LEADER` 和 `FIELD_MGR` 角色可见）。

* **3.2 项目面板工作区 (Project Workspace)**
  * **权限控制**：`SUPER_ADMIN`、`LEADER` 及被分配的项目管理人员拥有高级权限；现场直接参与人员有日常编辑权限；其余人员只读。
  * **UI 交互**：
    * **顶栏**：项目状态（`el-select` 下拉切换） + 显眼的**交底信息 (el-alert)** + `[修改管理人员]` 快捷入口（弹窗内使用 `el-select` 搜索并指派人员）。
    * **Tab 1: 动态、日志与工作段 (Sections & Logs)**：
      * 顶部 `[+ 创建工作段]`。
      * 工作段区块头部展示该段的**进度条 (`el-progress`)**。
      * 下方瀑布流展示日志，卡片点击出右侧抽屉 (`el-drawer`) 看详情。提供 `[+ 录入动态]`（录入表单中的班次、关联系等均使用下拉控件）。
    * **Tab 2: 相关设备与材料 (Equipment & Materials)**：
      * 列表/网格视图显示分配到该项目的设备材料。状态标签严格按红黄绿蓝规范显示。与库房调度底层数据实时联动。
    * **Tab 3: 文件库 (Files)**：
      * 大图标展示卡片，支持拖拽上传，通过下拉框按工作段过滤文件。

### 模块四：库房与资产 (Warehouse & Assets)
**可见角色：** `FIELD_MGR`, `SUPER_ADMIN` (及仓库专职人员)

* **4.1 资产设备台账 (Equipment Ledger)**
  * **UI 交互**：图片卡片流。高价值设备图片、编号、所处项目。提供 `[打印设备二维码]` 功能。

* **4.2 出入库制单工作台 (Order Creator)**
  * **UI 交互**：**左侧资源检索 + 右侧制单清单（购物车模式）**。
    * **检索面板**：提供支持模糊搜索的下拉框检索物资，支持扫码录入。本项目的现场管理员也可在此检索本项目的闲置物资用于平调。
    * **制单区**：下拉选择“调拨类型”，严格下拉指定源头与目的工地（如：`A项目 ➔ B项目`）。列表动态显示已选物品，数值微调使用 `el-input-number`。
    * **搭配模板**：提供 `[导入预设模板]` 下拉选择器，一键拉取。库存不足时自动红色预警。

* **4.3 搭配模板管理 (Combination Templates)**
  * **UI 交互**：列表维护页。使用抽屉表单预设常用的主从设备与材料组合。

* **4.4 双向对冲调度看板 (Two-way Dispatch Kanban)**
  * **UI 交互**：Trello 式拖拽看板，严格映射资金与物资的流转闭环。包含三种核心链路：
    1. **正向出库**：`总库房发货` ➔ `调拨运输中` ➔ `工地签收入库`
    2. **逆向退库**：`工地退回发出` ➔ `调拨运输中` ➔ `库房核验状态并签收`
    3. **工地间平调**：`源工地发出` ➔ `调拨运输中` ➔ `目标工地核验并签收`
  * **确认与状态核验**：发货方确认发出后卡片进入运输状态。接收方签收时弹出核验对话框 (`el-dialog`)，**必须通过下拉菜单重新评估设备当前状态**（良好/需维修/报废），并使用数字控件确认实际送达材料数量，提交后彻底闭环。

### 模块五：财务资金中枢 (Finance Center)
**可见角色：** `FINANCE`, `LEADER`, `SUPER_ADMIN` (发起对外付款向全员开放)

* **5.1 合同与付款监控大屏 (Contract Monitor)**
  * **UI 交互**：**高密度数据表格 (`ProTable`) + 进度条预警**。展示总额、已申请、已打款、剩余可用。超 90% 整行背景泛红/警告。

* **5.2 发起对外付款 (Initiate External Payment)**
  * **UI 交互**：单框输入金额（`el-input-number`）实时校验阈值。触发“新建合同向导”时，关联项目、收款人等信息强制使用 `el-select` 模糊搜索下拉选择。

* **5.3 报销批次打款台 (Reimbursement Batch)**
  * **UI 交互**：嵌套表格（展开行）。主行显示批次；展开显示报销人的**收款银行账户**。点击 `[登记打款执行]` 弹出抽屉。

* **5.4 财务报表快照 (Financial Snapshot)**
  * **UI 交互**：ECharts 仪表盘。高管专用的大盘视图。

### 模块六：系统底层与引擎管理 (Admin Settings)
**可见角色：** `SUPER_ADMIN` (严格隔离)

* **6.1 审批流程设计器 (Workflow Designer)**
  * **UI 交互**：全屏可视化画布 (`@vue-flow/core`)。选中节点从右侧拉出抽屉，下拉选择审批角色，数字输入框填写超时时间。

* **6.2 阈值管控中心 (Threshold Rules)**
  * **UI 交互**：规则列表页。配置金额区间及绑定的对应下拉审批模板。

* **6.3 自动化与 AI 引擎监控 (AI & Runner Center)**
  * **UI 交互**：代码编辑器（Monaco）高亮维护 Prompt；心跳仪表盘监控任务队列。

* **6.4 实体与基座管理 (System Base)**
  * **UI 交互**：维护公司实体。字典管理中严格维护供全系统下拉框引用的基础映射字典项。

* **6.5 企业微信集成 (WeCom Integration)**
  * **UI 交互**：凭证配置表单与同步操作面板。

* **6.6 业务数据全量运维台 (Raw Data Operations)**
  * **UI 交互**：**左树右表布局**。高度封装的通用动态表格（ProTable）。顶部红色警告。供超管进行无限制的查改删。

* **6.7 IT 支持与工单处理台 (Helpdesk)**
  * **UI 交互**：工作台列表。点击单行记录弹出详情抽屉，管理员可查阅错误截图并填写“处理说明/解决方案”。

## 4. 前端落地建议路径 (Sprint 规划)

**Sprint 1: 拆旧建新与工作台**
* 抹除旧菜单，搭建基于 Roles 的路由守卫（Vue Router `beforeEach`）。
* 完成模块一（个人工作台）和模块二（统一审批台），保证所有角色登录后不报错，能处理审批。
* *要求：严格落实下拉选择与卡片视图规范。*

**Sprint 2: 现场、项目与智能库房**
* 聚焦模块三，使用卡片流（Masonry）重构动态日志，实现工作段进度条关联。
* 同步上线模块四，实现基于“购物车+下拉检索”的制单台、模板管理及包含状态重检的拖拽调度流转逻辑。

**Sprint 3: 财务堡垒与大屏**
* 聚焦模块五。实现带有进度条预警的高密度财务宽表。
* 实现最复杂的“金额阈值智能分支”发单向导，打通全员发起对外付款的权限。

**Sprint 4: 超管可视化工具与排障控制台**
* 引入 `@vue-flow/core` 完成审批流程设计器。
* 接入 ECharts 完成高管视角的财务快照。
* 补齐企业微信等系统级对接配置面板，并完成底层业务数据运维台及全员工单处理台。
