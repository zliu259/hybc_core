# 库房小程序任务执行接口规划

## 1. 定位

本文件定义库房操作员小程序执行端的稳定后端契约。小程序页面后续实现，当前阶段先固定接口、字段和权限边界，减少小程序发版审核带来的变更成本。

## 2. 设计原则

- 小程序只做执行，不做最终派工、不做复杂方案制定。
- 任务类型、照片要求、手册内容、步骤配置由后端下发。
- 操作员只能看到分配给自己的任务。
- 任务提交必须校验当前用户是执行人，`super_admin` 仅用于排障和代处理。
- 任务完成后的照片、简报、附件进入 `warehouse_task_evidence`，并能从设备详情追溯。

## 3. 当前接口

接口挂载在现有库房工单路由下：`/api/v1/warehouse/work-order/mobile/*`。

### 3.1 执行配置

`GET /api/v1/warehouse/work-order/mobile/config`

返回：

- `contract_version`: 当前契约版本，当前为 `1`。
- `visible_statuses`: 小程序可见任务状态。
- `evidence_types`: 支持的证据类型，包含 `photo`、`video`、`voice`、`brief`、`document`。
- `actions`: 支持动作，当前为 `start`、`submit`。
- `min_photo_count_source`: 照片数量来源字段，当前为 `required_photo_count`。
- `manual_source`: 手册版本来源字段，当前为 `manual_version_id`。

### 3.2 我的任务包

`GET /api/v1/warehouse/work-order/mobile/package`

返回当前用户作为 `assignee_userid` 的任务包，状态范围为 `open`、`in_progress`、`exception`。

### 3.3 我的任务

`GET /api/v1/warehouse/work-order/mobile/my-tasks`

返回当前用户作为 `assignee_userid` 且 `mobile_enabled = 1` 的任务。当前可见状态为：

- `assigned`
- `in_progress`
- `rejected`

排序规则：

1. `urgent`
2. `high`
3. `normal`
4. `low`
5. 计划日期
6. 最新任务

### 3.4 任务详情

`GET /api/v1/warehouse/work-order/mobile/task/:id`

返回：

- 任务主数据。
- `manual_title`、`manual_version_no`、`manual_content`。
- `steps`: 后端配置步骤。
- `evidence`: 已提交证据。

权限：

- `super_admin` 可查看。
- 其他角色只能查看分配给自己的任务。

### 3.5 开始任务

`POST /api/v1/warehouse/work-order/mobile/task/:id/start`

约束：

- 任务必须可在小程序执行。
- 当前用户必须是任务执行人，或为 `super_admin`。
- 只有 `assigned` 状态可开始。
- 已是 `in_progress` 时重复调用返回成功。

### 3.6 提交任务

`POST /api/v1/warehouse/work-order/mobile/task/:id/submit`

请求体：

```json
{
  "result_summary": "检查通过，已完成清洁和润滑",
  "completion_summary_json": "{\"result\":\"pass\"}",
  "evidence": [
    {
      "evidence_type": "photo",
      "file_key": "r2://bucket/path/photo.jpg",
      "file_name": "检查照片.jpg",
      "summary": "机芯铭牌与外观",
      "captured_at": "2026-05-05T03:00:00.000Z"
    }
  ]
}
```

约束：

- 当前用户必须是任务执行人，或为 `super_admin`。
- `required_photo_count > 0` 时，提交照片数量必须满足要求。
- 提交后任务进入 `submitted`，等待 Web 管理端负责人复核。

## 4. 小程序页面后续实现

后续页面建议：

- `pages/warehouse/index`: 任务首页。
- `pages/warehouse-task/index`: 我的任务列表。
- `pages/warehouse-task-detail/index`: 任务详情、手册、步骤。
- `pages/warehouse-task-submit/index`: 拍照、语音、简报提交。

## 5. 不在小程序实现的能力

- 最终派工。
- 顶管机组合方案制定。
- 操作手册发布。
- 阻塞出库的强制放行。
- AI 调度建议确认。
